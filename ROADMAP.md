# fmc-mcp-server roadmap
_Last updated 2026-10-16: logs and events are pull-only ([ADR-003](https://github.com/dr-stutters/stutters-mcp-core/blob/main/docs/adr/003-no-event-ingestion.md)); F7 (FTD syslog) and F12 (eStreamer) dropped, F5 reframed as on-demand activity lookups. Current release **v0.10.0** (F13 identity: AD realms, identity policies, access rules on users and groups) (Now, Next and the Production gate delivered except F17; Later: F13 intrusion/decryption/DNS, F14, F20-F25; F15 cdFMC open; F13 identity delivered in v0.10.0). Suite roadmap: [stutters-mcp-core ROADMAP.md](https://github.com/dr-stutters/stutters-mcp-core/blob/main/ROADMAP.md). Gap analysis: [docs/GAP-ANALYSIS.md](docs/GAP-ANALYSIS.md)._

## Summary
- v0.4.0 has 45 read, 35 write and 7 dangerous tools plus the `fmc_why_blocked` and `fmc_onboard_ftd` prompts (v0.3.0: 41/30/7; v0.2.0: 35/20/7). The day-to-day firewall workflows are curated and were live-tested against FMC 10.0.1 with an FTDv 10.0 in CML: onboard, change → preview → deploy → verify → roll back, "why is this blocked?" and device health. 17 % of the 1446 API operations are behind curated tools; most of the rest go through `fmc_api_call`.
- The biggest gaps are routing beyond static routes, VPN build, platform settings (syslog, NTP, SNMP), editing the intrusion, decryption, DNS and identity policies, and a merged view of recent health alerts, audit and deployments. The FMC REST API has **no connection or intrusion events and no packet capture**; under ADR-003 the server doesn't receive FTD syslog or eStreamer, so traffic events stay in the FMC UI or the customer's SIEM.
- HA (form, monitoring, switch, break, delete) and a policy-based site-to-site VPN were tested live on three FTDv in v0.4.0; clustering, route-based VPN, SD-WAN and RA VPN are tested only against mocks. The lab only covers FMC 10.0.1, with one domain and the shared `admin` user.
- **Now** ✅ delivered in v0.3.0 (core pinned to v0.3.0):
  - the `fmc_why_blocked` prompt;
  - platform-settings tools (syslog read/write; NTP, SNMP and access settings read);
  - dynamic-object mappings for rapid threat containment (block without a deploy, verified live);
  - on-demand lookups of health alerts, audit records and deployments (`fmc_list_health_alerts`, `fmc_recent_activity`);
  - BGP, OSPF and VRF tools (`fmc_get_routing`, `fmc_configure_bgp`, `fmc_configure_ospf`, `fmc_create_vrf`/`fmc_delete_vrf`), live against an IOL peer;
  - the duplicate static-route blocker.
- **Next** ✅ delivered in v0.4.0 (core v0.6.0): live HA with two FTDv, VPN build and read, `fmc_onboard_ftd`, and `fmc_contain_host`/`fmc_release_host` for ise-mcp-server's `ise_quarantine_host`. **Later** covers editing the security policies, admin operations and cdFMC. FTD syslog (F7) and eStreamer (F12) were dropped: the servers never receive pushed data.

## Logs and events (pull-only, ADR-003)
Every tool queries FMC when called ([ADR-003](https://github.com/dr-stutters/stutters-mcp-core/blob/main/docs/adr/003-no-event-ingestion.md)). No syslog receiver, eStreamer client, pollers or buffers; the history available is what FMC keeps.

| Tool | What it reads | Status |
|---|---|---|
| `fmc_list_audit_records` | FMC audit log over a window: who did what (logins, policy edits, API calls, deploys) | ✅ v0.2.0 |
| `fmc_list_deployments` | Deployment jobs over a window, per device: when, by whom, status | ✅ v0.2.0 |
| `fmc_device_health` | Current health of one FTD: non-green modules, CPU, memory | ✅ v0.2.0 |
| `fmc_list_health_alerts` (F5) | Health alerts across devices over a window (repeats collapsed) | ✅ v0.3.0 |
| `fmc_recent_activity` (F5) | Health alerts + audit records + deployments, merged by time | ✅ v0.3.0 |
| Connection, intrusion, file and malware events | **Not in the FMC REST API.** Not received by this server (ADR-003); use the FMC UI or the customer's SIEM | ❌ out of scope |
| Packet capture | **Not in the FMC 10.0.1 REST API** (only PCAP upload for packet tracer replay); the FTD CLI `capture` isn't on the show-command allowlist | ❌ not planned |

## Not planned
These are left to `fmc_api_call` or out of scope.
- **Packet capture:** not in the FMC 10.0.1 REST API. Use the FMC UI or the FTD CLI.
- **The pending-changes CLI preview (`CLI_DIFF`):** the result is a PDF inside a ZIP. `fmc_pending_changes` covers previews.
- **Multipart uploads and binary downloads:** Secure Client packages, custom SI lists, intrusion rule upload, PCAP replay, bulk registration CSV, backup and report downloads. MCP can't carry them usefully.
- **Clustering create and readiness:** no cluster-capable lab. It stays read-only (`fmc_list_clusters`) plus `fmc_api_call`. This could be revisited after F10 if FTDv clustering on KVM fits the CML budget.
- **Running upgrades from chat:** long, high-risk tasks. F14 reads status only.
- **Chassis and multi-instance, device templates, zero trust, TID, network map, integrations (Umbrella, AIOps, external storage), DHCP/DDNS:** low operator value for this server. Use `fmc_api_call`.
- **Creating FMC users or roles:** the API is read-only for them. F16 documents the UI steps.
