# fmc-mcp-server roadmap
_Last updated 2026-10-15. Current release v0.2.0. Suite roadmap: [stutters-mcp-core ROADMAP.md](https://github.com/dr-stutters/stutters-mcp-core/blob/main/ROADMAP.md). Gap analysis: [docs/GAP-ANALYSIS.md](docs/GAP-ANALYSIS.md)._

## Summary
- v0.2.0 has 35 read, 20 write and 7 dangerous tools. The day-to-day firewall workflows are curated and were live-tested against FMC 10.0.1 with an FTDv 10.0 in CML: onboard, change → preview → deploy → verify → roll back, "why is this blocked?" and device health. 17 % of the 1446 API operations are behind curated tools; most of the rest go through `fmc_api_call`.
- The biggest gaps are routing beyond static routes, VPN build, platform settings (syslog, NTP, SNMP), editing the intrusion, decryption, DNS and identity policies, and events. The FMC REST API has **no connection or intrusion events and no packet capture**, so events have to come from FTD syslog or eStreamer.
- HA, clustering and VPN tunnel status are tested only against mocks. The lab only covers FMC 10.0.1, with one domain and the shared `admin` user.
- **Now** adds:
  - the `fmc_why_blocked` prompt;
  - platform-settings tools, which are the first step for FTD syslog;
  - dynamic-object mappings for rapid threat containment;
  - an event source that polls FMC health alerts and audit records and needs no appliance setup;
  - BGP and OSPF depth;
  - the core v0.1.2 bump and the deferred review nit.
- **Next** adds the FTD syslog receiver, live HA with two FTDv, VPN build, and the `fmc_onboard_ftd` and `ise_quarantine_host` workflows. **Later** covers eStreamer, editing the security policies, admin operations and cdFMC.

## Not planned
These are left to `fmc_api_call` or out of scope.
- **Packet capture:** not in the FMC 10.0.1 REST API. Use the FMC UI or the FTD CLI.
- **The pending-changes CLI preview (`CLI_DIFF`):** the result is a PDF inside a ZIP. `fmc_pending_changes` covers previews.
- **Multipart uploads and binary downloads:** Secure Client packages, custom SI lists, intrusion rule upload, PCAP replay, bulk registration CSV, backup and report downloads. MCP can't carry them usefully.
- **Clustering create and readiness:** no cluster-capable lab. It stays read-only (`fmc_list_clusters`) plus `fmc_api_call`. This could be revisited after F10 if FTDv clustering on KVM fits the CML budget.
- **Running upgrades from chat:** long, high-risk tasks. F14 reads status only.
- **Chassis and multi-instance, device templates, zero trust, TID, network map, integrations (Umbrella, AIOps, external storage), DHCP/DDNS:** low operator value for this server. Use `fmc_api_call`.
- **Creating FMC users or roles:** the API is read-only for them. F16 documents the UI steps.
